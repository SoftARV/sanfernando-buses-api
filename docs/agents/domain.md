# Domain docs

## Before exploring

This repo uses a single-context layout.

Read root `CONTEXT.md` for domain terminology and relevant ADRs
under `docs/adr/` for decisions affecting the work.

If these files are absent, proceed silently. Domain-modeling work
creates them when terms or decisions are resolved; setup does not
create placeholder domain documents.

## Vocabulary

Use the terms defined in `CONTEXT.md` in issues, proposals, tests,
and code. Note missing concepts for domain-modeling when relevant.

## Decisions

If a proposal contradicts an ADR, identify the ADR and explain
why the decision should be reconsidered.
